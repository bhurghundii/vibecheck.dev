Not quite: "So it works better." Bold. Anything under 500 breaks out on the first try and goes straight into raise_for_status(). Retrying a 403 three times was never going to fix your token. // the problem

Thanks to AI, it is far easier to generate code that nobody understands. The burden of understanding falls on the reviewers, and when they face a pile of massive PRs nobody has the energy to read closely, the result is burnout and rubber-stamping.

Then you are shipping code that nobody understands. For business critical software, that is simply unacceptable.

vibecheck keeps a human in the loop who knows what the change does, before a reviewer spends an hour on it.

// how it works

One workflow file. One link on the PR. No understanding, no merge.

Run vibecheck on your own server and add a single GitHub Actions workflow to your repo. From then on, every pull request gets an exam sheet.

  1. It reads the change

    vibecheck reads the diff, forms its own blind interpretation, writes a few questions, and comments on the PR with a link.

  2. The author answers

    One question per screen, next to the slice of the diff it is about, in plain English. The first is always: how does this change work at a high level?

  3. Claude grades it

    Each answer is marked against the actual change. Terse but correct passes. Contradicting the diff fails. You tune how much detail a pass needs.

  4. The check decides

    Pass enough questions and vibecheck/verdict goes green. Fall short and the merge stays blocked.

// features

Built to be annoying in exactly one way.

Everything else stays out of your way: no app to install, no OAuth dance, no runner sitting idle while someone thinks.

An exam sheet for every PR

A fixed high-level question plus scoped questions, each anchored to a specific part of the diff.

Sized to the change

One scoped question per 15 changed lines, up to a cap. A one-line PR gets one question. A 1,000-line monstrosity gets picked apart.

Graded leniently

Wrong answers can be retried, then the answer is revealed. "Explain it for me" walks through a section with no effect on the mark.

A real merge gate

Require vibecheck/verdict in branch protection and the PR cannot merge until the author passes. Leave it optional for advisory mode.

Good practice checks

Oversized PRs and diffs are rejected before a single question is asked, with the reason commented on the PR.

Local first

Self-hosted only. One Docker Compose command and it is running, enterprise network included. Bring your own Anthropic key.

No GitHub App, no webhooks

A FastAPI service that a GitHub Action talks to over a bearer token. Nothing to install on GitHub beyond a workflow file.

Fork PRs covered

Drive-by PRs from forks are gated too, without ever checking out or running their code.

Sarcastic mode

Use vibecheck the way God intended: a grumpy senior who brutally tears apart your understanding. Off by default.

// quickstart

Running locally in about a minute.

  • Self-hosted. A Docker image on ghcr.io/bhurghundii/vibecheck.dev plus a Postgres database, on your server or cloud account.
  • Free to try. The fake grader is on by default, so you can see the whole flow with zero API cost.
  • Then wire it up. Add the workflow, set two repo secrets, and require the check.
